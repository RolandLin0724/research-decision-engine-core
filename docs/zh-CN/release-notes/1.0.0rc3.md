## RDE Core 是什么

RDE Core 是一个本地 Python 研究核心，用于在有限且有序的候选集合上进行有界、
顺序式实验选择。它结合了确定性的内置策略、受信任的本地工作负载适配器、由
SQLite 支持的历史记录、中断与恢复，以及可验证和回放的可移植 RunBundle。

Core 界定的是研究执行与制品兼容性边界。它不证明科学正确性，不复现外部执行
环境，不确立生产就绪状态，也不为单独治理的 RDE Assurance 产品线创建权限或
批准。

## 亮点

- 在有限候选集合上执行有界实验。
- 通过 `PythonFunctionAdapter` 和 `CommandAdapter` 支持受信任的本地工作负载。
- 在各自支持的 schema 版本中提供 `random`、`greedy_prior` 和
  `information_gain_table` 策略。
- 在本地 SQLite 中持久化已完成的执行历史。
- 支持从已完成历史中断后进行确定性恢复。
- 导出并验证带版本的 RunBundle。
- 使用已记录观测回放决策过程，而不再次执行工作负载。
- 提供语义对应的英文和简体中文用户文档。
- 在 CPython 3.12 上通过 Windows 和 Linux CI 检查 Core 合同。
- 使用 Apache-2.0 许可证。

## 支持的合同

- **Python：**CPython `>=3.12,<3.13`。
- **公共 API：**恰好 112 个清单列出的符号。可导入的内部模块并不是公共 API。
  在现有 RDE 1.x RC 合同下，已记录的公共签名、不可变公共字段和类型化错误族
  都承载兼容性。
- **RunSpec、RunBundle、策略与回放：**

  | 版本 | 支持的策略 | 回放合同 |
  | --- | --- | --- |
  | v1 | `random` | `RECORDED_OBSERVATION_DECISION_REPLAY_V1` |
  | v2 | `random`、`greedy_prior` | `RECORDED_OBSERVATION_DECISION_REPLAY_V2` |
  | v3 | `random`、`greedy_prior`、`information_gain_table` | `RECORDED_OBSERVATION_DECISION_REPLAY_V3` |

  RunSpec 与 RunBundle 版本必须匹配。Core 不执行静默升级或降级。未知 schema
  或策略组合会以失败关闭。候选顺序与规范身份都承载兼容性。
- **SQLite：**最新 schema 为 v6。受支持的旧版 schema 通过原子且可恢复的步骤
  每次向前迁移一个版本。
- **打包：**文档对齐后的候选合同是恰好包含 121 个成员的规范化源码分发包：
  91 个包成员、27 个公共文档成员和 3 个构建/许可成员。`.github` 社区健康文件
  仍仅属于仓库，并排除在源码分发包之外。私有或原始的审计、恢复、历史以及
  Assurance 证据或材料仍排除在公共产品源码分发包之外。
- **平台：**Windows 与 Linux 有 CI 支持。本草案不声称 macOS 有 CI 支持。

## 升级与 SQLite 迁移说明

本说明描述的历史软件包版本为 `1.0.0rc3`。RunSpec 与 RunBundle 制品不会被重写
或静默转换。历史规范 RunBundle 夹具保留其 `0.1.0` 生产者身份，RC3 生成的 bundle
记录 `1.0.0rc3`。当前私有候选现为 `1.0.0rc5`，由它新生成的 bundle 记录
`1.0.0rc5`；必须使用与制品 v1、v2 或 v3 完全匹配的 API。

新初始化的数据库使用 SQLite schema v6。受支持的旧版 schema v1 至 v5 每次
向前迁移一个版本，直至 v6。每条迁移边都是原子且可恢复的：当前迁移边失败会
回滚到其源状态，之前已提交的迁移边保持已提交，之后重试会从最后提交的版本
恢复。未知的未来 schema 在变更前以失败关闭。不支持降级。迁移重要数据库前
应先备份。

## RunBundle 验证与回放行为

RunBundle 验证是只读且失败关闭的。它会检查封闭的规范 schema、版本与策略
绑定、承载身份的各部分、SHA-256 sidecar、决策与理由一致性、有序候选身份、
生产者元数据形状，以及源身份和祖先约束。这些完整性检查可以检测篡改；它们
不是数字签名、签名者身份、第三方证明或科学验证。

回放对 v1、v2 和 v3 执行版本匹配。它使用已记录观测重新计算并比较确定性的
Core 决策、理由、终止摘要和适用的信念谱系，然后重建全新的 SQLite 状态。回放
不接收工作负载适配器、callable、命令构建器、命令或插件，也不执行它们。不支持
任意导入路径、注册表、URL 或插件加载。回放不会重建原始操作系统、Python
环境、可执行文件、依赖项、文件、服务、硬件或其他外部状态。

## 安全与信任边界

- `PythonFunctionAdapter` 在当前 Python 进程中运行用户提供的 callable；
  `CommandAdapter` 以当前用户权限启动本地子进程。两者都要求受信任的代码。
- 两种适配器都不是恶意代码沙箱、容器、秘密管理器或安全隔离边界。
- RunSpec、SQLite 数据库、命令输出和 RunBundle 可能包含用户提供的数据。用户
  必须避免在这些表面放入秘密，并在共享制品前完成净化。
- 回放的不执行边界并不证明原始工作负载或其观测是真实的。
- 双语安全策略和隐私/秘密公开发布门禁已经存在，但该公开发布门禁尚未完成。
- RDE Core 结果不会创建 RDE Assurance 权限、批准、审查封印或科学证明。

## 已知限制

- 这是预发布软件；不存在公开的 Core v1.0 或 RC 版本。
- 仅支持 CPython 3.12（`>=3.12,<3.13`）。
- 工作负载在受信任的本地进程边界内运行。
- 不提供恶意代码沙箱。
- 不要求 GPU，也不提供 GPU 执行器。
- 不提供集群执行器。
- 不提供 Web UI。
- RDE Core 不包含 Continual Learning。
- Core 不创建 RDE Assurance 批准。
- 回放不会重建原始外部环境。
- `information_gain_table` 的似然模型由用户声明；Core 不学习该模型，也不对其
  进行科学验证。
- 不作生产就绪声明。
